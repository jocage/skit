# Skit — Product Specification

Opinionated Next.js SaaS starter generated by `npx create-skit`. This document describes the full shape of every generated app for mockup and design purposes.

---

## 1. CLI Options

The generator prompts for these choices. Each can also be passed as a flag.

| Prompt | Flag | Values | Default |
|---|---|---|---|
| Project name | positional arg | any string | `my-skit-app` |
| Template | `--template` | `blank`, `dashboard` | `blank` |
| Architecture | `--architecture` | `route-colocated`, `feature-first`, `monorepo-ready` | `route-colocated` |
| Package manager | `--package-manager` | `pnpm`, `npm`, `bun` | `pnpm` |
| Postgres driver | `--database-driver` | `pg`, `postgres.js` | `pg` |
| Billing | `--billing` | `stripe`, `polar`, `both`, `none` | `stripe` |
| Auth | `--auth` | `email-password`, `email-password+github`, `email-password+google`, `email-password+github+google` | `email-password` |
| Email provider | `--email-provider` | `resend`, `none` | `resend` |
| Deploy target | `--deploy-target` | `vercel`, `docker` | `vercel` |
| Seed demo data | `--seed-demo-data` | `yes`, `no` | `yes` |
| AI tools | `--ai-tools` | `cursor`, `claude`, `gemini`, `copilot`, `all`, `none` | none |

The generator writes a `skit.json` config at the project root recording every selection.

## 2. Templates

### `blank`

Minimal SaaS shell. A clean landing page with navigation, sign-in and sign-up links, and a single protected `/dashboard` route that proves auth is wired.

**Landing page** (`/`): header with project name + nav links (Sign in / Get started), hero section with heading "Your SaaS starts here."

**Dashboard page** (`/dashboard`): protected, shows authenticated user's name/email, links to Billing and Email surfaces.

### `dashboard`

Marketing-first layout with a public demo dashboard. The demo dashboard is visible without auth — session context unlocks real interactivity.

**Landing page** (`/`): marketing nav, hero section, bento-grid feature showcase (auth, billing, database, email, testing, Next.js, agent-friendly), 3-tier pricing grid, CTA section, footer.

**Dashboard page** (`/dashboard`): public demo (no auth required to view). Sidebar nav with brand, workspace indicator, links. Stats bar (MRR, Trials, Activation, Churn). Activity feed, mini insight cards (Auth / Deploy / Billing), growth pipeline section.

## 3. Routes

All generated apps share this route structure:

| Route | Protected | Description |
|---|---|---|
| `/` | No | Home / landing page |
| `/sign-in` | No | Email + password sign-in. Social buttons injected by auth module |
| `/sign-up` | No | Email + password account creation. Social buttons injected by auth module |
| `/dashboard` | blank: yes / dashboard: no | Main protected surface or public demo |
| `/billing` | blank: yes / dashboard: no | Billing provider checkout cards |
| `/email` | blank: yes / dashboard: no | Transactional email test surface |
| `/settings` | dashboard only | Account settings page |
| `/api/auth/[...all]` | — | Better Auth catch-all handler |
| `/api/billing/checkout` | — | POST — initiates provider checkout session |
| `/api/billing/portal` | — | POST — opens billing portal |
| `/api/email/test` | — | POST — sends a test email |
| `/api/webhooks/stripe` | — | Stripe webhook receiver (pruned if no Stripe) |
| `/api/webhooks/polar` | — | Polar webhook receiver (pruned if no Polar) |
| `/llms.txt` | — | LLM-friendly project manifest |
| `/llms-full.txt` | — | Extended LLM manifest |

Route protection is enforced by `middleware.ts` using Better Auth session checks.

## 4. Auth Surfaces

### Sign-in page

- Heading and lede copy differ by template (blank: "Sign in to your workspace", dashboard: "Sign in")
- Email input + password input
- Submit button ("Sign in" / "Continue")
- Link to sign-up
- Social buttons injected below a divider ("or continue with") if a social provider is selected

### Sign-up page

- Same structure as sign-in with registration copy
- Social buttons conditionally injected

### Social buttons (injected by module)

- **GitHub**: "Continue with GitHub" button calling `authClient.signIn.social({ provider: "github" })`
- **Google**: "Continue with Google" button calling `authClient.signIn.social({ provider: "google" })`

---

## 5. Billing Surface (`/billing`)

Shows checkout cards for each active billing provider.

**blank template (auth-guarded)**:
- Each provider has a card with heading (Stripe / Polar), description, and a form POST button
- Buttons: "Start Stripe checkout" / "Start Polar checkout"

**dashboard template (public demo)**:
- Same cards but with a demo banner when no session: "Demo mode is active. Checkout buttons stay visible for product context..."
- Buttons disabled for unauthenticated users: "Sign in to test Stripe" / "Sign in to test Polar"
- Shows `displayBillingUser.name` in caption

---

## 6. Email Surface (`/email`)

Test surface for transactional email.

**blank template**: auth-guarded, recipient is `session.user.email`, send always enabled.

**dashboard template**: public demo with banner when no session: "Demo mode is active. The email surface stays visible, but actual send actions unlock after sign-in..."

## 7. Module System

Each option maps to one or more modules. The generator resolves a topologically sorted module graph.

### Core modules (always included)

| Module | Kind | What it provides |
|---|---|---|
| `quality-baseline` | dx | ESLint, Prettier, Husky, lint-staged |
| `testing-baseline` | dx | Vitest, Playwright, CI configs |
| `auth-core` | auth | Better Auth wiring, session helpers, protected routes, sign-in/sign-up pages |

### Database (exactly one)

| Module | Trigger | What it provides |
|---|---|---|
| `db-pg` | `--database-driver pg` | Drizzle + `pg` pool, global singleton pattern |
| `db-postgresjs` | `--database-driver postgres.js` | Drizzle + `postgres` client |

### Auth social providers (additive)

| Module | Trigger | What it provides |
|---|---|---|
| `auth-github` | `+github` in auth option | GitHub OAuth config, social button, env vars |
| `auth-google` | `+google` in auth option | Google OAuth config, social button, env vars |

### Billing (zero to two)

| Module | Trigger | What it provides |
|---|---|---|
| `billing-stripe` | `stripe` or `both` | Stripe provider class, webhook route, package dep |
| `billing-polar` | `polar` or `both` | Polar provider class, webhook route |

When no billing module is selected, both provider files and webhook routes are pruned from the output.

### Email (zero or one)

| Module | Trigger | What it provides |
|---|---|---|
| `email-resend` | `--email-provider resend` | Resend client, send implementation, package dep |

When no email module is selected, the email layer is scaffolded but the send function returns `{ skipped: true, provider: "none" }`.

### Deploy (optional)

| Module | Trigger | What it provides |
|---|---|---|
| `deploy-docker` | `--deploy-target docker` | `Dockerfile`, `.dockerignore` |

### UI shell (template-driven)

| Module | Trigger | What it provides |
|---|---|---|
| `dashboard-shell` | `dashboard` template | `src/app/globals.css` (dashboard styles), `src/app/settings/page.tsx` |

### AI tools (zero to four, additive)

| Module | Trigger | What it provides |
|---|---|---|
| `ai-dx` | any AI tool selected | `AGENTS.md`, `ARCHITECTURE.md` |
| `ai-dx-cursor` | `cursor` | `.cursor/rules/*.mdc` (6 rule files) |
| `ai-dx-claude` | `claude` | `CLAUDE.md` |
| `ai-dx-gemini` | `gemini` | `.gemini/GEMINI.md` |
| *(copilot)* | `copilot` | No extra files — uses shared `AGENTS.md` only |

```
      email/test/route.ts         POST test send

      webhooks/polar/route.ts     Polar webhooks (pruned if no Polar)
    llms.txt/route.ts             LLM manifest

  components/
    auth/
      email-auth-form.tsx         sign-in/up form component (social buttons injected)
      email-auth-form.test.tsx    unit tests
      sign-out-button.tsx         sign-out action button
  db/
    index.ts                      Drizzle db instance (driver-specific)
    schema/
      auth.ts                     Better Auth schema (generated)
      index.ts                    schema barrel
      projects.ts                 example projects table
    seeds/
      index.ts                    demo seed data
  lib/
    auth.ts                       Better Auth server config (social providers injected)
    auth-client.ts                Better Auth browser client
    auth-session.ts               server session helper
    billing/
      index.ts                    getBillingProvider() factory
      types.ts                    BillingProvider interface
      providers/
        stripe.ts                 Stripe implementation (pruned if not Stripe)
        polar.ts                  Polar implementation (pruned if not Polar)
    email/
      index.ts                    sendEmail() — provider-swappable
      templates.ts                HTML email template factories
      templates.test.ts           template unit tests
    env.ts                        Zod-validated environment (server-only)
middleware.ts                     Route protection + auth session check
```

## 9. Environment Variables

```bash
# Required
NEXT_PUBLIC_APP_URL=http://localhost:3000
BETTER_AUTH_URL=http://localhost:3000
DATABASE_URL=postgresql://postgres:postgres@localhost:5432/<project>
BETTER_AUTH_SECRET=replace-me

# Provider selection (set by generator, runtime-configurable)
BILLING_PROVIDER=stripe         # stripe | polar | both | none
EMAIL_PROVIDER=resend           # resend | none

# Resend (email-provider=resend)
RESEND_API_KEY=re_xxx
EMAIL_FROM=App Name <onboarding@example.com>

# Stripe (billing=stripe or both)
STRIPE_SECRET_KEY=sk_test_xxx
STRIPE_PRICE_ID=price_xxx
STRIPE_WEBHOOK_SECRET=whsec_xxx

# Polar (billing=polar or both)
POLAR_ACCESS_TOKEN=polar_pat_xxx
POLAR_ORGANIZATION_ID=org_xxx
POLAR_PRODUCT_ID=prod_xxx
POLAR_SERVER=sandbox             # sandbox | production
POLAR_WEBHOOK_SECRET=polar_whsec_xxx

# GitHub OAuth (auth=..+github)
GITHUB_CLIENT_ID=github_oauth_client_id
GITHUB_CLIENT_SECRET=github_oauth_client_secret

# Google OAuth (auth=..+google)
GOOGLE_CLIENT_ID=google_oauth_client_id
GOOGLE_CLIENT_SECRET=google_oauth_client_secret
```
